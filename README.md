# pdm-gru

Predictive maintenance on the NASA C-MAPSS turbofan degradation dataset (FD001). Two independent pipelines live in this repo:

- **`rul/`** — Remaining Useful Life regression: predict how many cycles an engine has left, via a GRU seq2seq model with additive attention (with an optional quantum-layer variant of the encoder).
- **`ad/`** — Anomaly Detection: a GRU-VAE trained only on healthy engine data, used to flag abnormal sensor windows via reconstruction error, with no failure labels involved in training (with an optional quantum-circuit variant of the model, `--model quantum`).

Both read the same raw C-MAPSS files under `data/` (`train/train_FD001.txt`, `test/test_FD001.txt`, `RUL_FD001.txt`) but preprocess and model them independently — there's no shared code between the two folders.

## Data layout

```
data/
  train/train_FD001.txt   # 26 whitespace-separated columns: unit, cycle, 3 op settings, 21 sensors
  test/test_FD001.txt     # same columns, truncated engine trajectories
  RUL_FD001.txt           # one true RUL value per test engine, in engine order
  synthetic/               # generated by ad/datagen.py, see below
```

---

## RUL

Location: `rul/`. Trains a GRU encoder → additive-attention GRU decoder (`rul/models/classical.py`) to regress remaining cycles directly from raw sensor windows, using the standard C-MAPSS piecewise-linear RUL target (clipped at `--max-rul`, default 125). `rul/models/quantum.py` swaps in a variational quantum circuit (PennyLane, simulated) between the encoder's final hidden state and the decoder, as an alternate encoder (`--model quantum`).

### Running it

Like `ad/`, everything runs from the repo root (`rul/train.py`/`rul/infer.py` use package-relative imports, e.g. `from rul.data import ...`):

```bash
python -m rul.train --subset FD001 --epochs 15
# add --model quantum to use the PennyLane-based encoder instead of the default GRU one
```

This holds out `--val-fraction` (default 0.15) of the training engines for validation (the feature scaler is fit only on the remaining train engines, so nothing about val or test leaks into it), trains with early stopping (`--patience`, default 5 epochs without val-loss improvement) up to `--epochs` (default 15, a cap rather than a fixed count), then evaluates against the held-out test engines (RMSE/MAE averaged over the last `--num-test-windows` windows, RMSE/MAE on the single last window, and the NASA S-score) and saves a checkpoint (model weights + both fitted scalers + all hyperparameters needed to reload it) to `--save-path` (default `./saved_weights/seq2seq_rul.pt`). Any engine shorter than `--window-length` is skipped with a printed warning rather than crashing the run.

To visualize predictions from a saved checkpoint:

```bash
python -m rul.infer --checkpoint ./saved_weights/seq2seq_rul.pt \
  --mode overall                 # predicted vs. true RUL across the whole test fleet
python -m rul.infer --checkpoint ./saved_weights/seq2seq_rul.pt \
  --mode engine --engine-id 24   # full predicted RUL trajectory for one engine
```

Both modes save a `.png` (`--output`, default `rul_predictions.png`) and can `--show` interactively.

## AD

Location: `ad/`. Trains a GRU-VAE (`ad/models/classical.py`) on **healthy-only** windows (`RUL >= healthy_rul_threshold`, default 100) — the model never sees failure data or labels during training. Anomalies are then detected purely from reconstruction error at inference time: healthy windows reconstruct well, anomalous ones don't. `ad/models/quantum.py` swaps in a PennyLane variational circuit as an alternate model (`--model quantum`), in one of two modes (`--quantum_mode`): `bottleneck` (default) keeps the GRU encoder/decoder classical and only makes the latent `mu`/`logvar` come off PauliZ expectations instead of a plain linear layer, while `full` replaces the encoder and decoder with quantum-gated (QLSTM) recurrent cells as well.

### Pipeline

```
ad/data.py      prepare_data(): loads C-MAPSS, splits engines train/val/test (random,
                seeded), keeps only healthy rows, fits a StandardScaler on train only,
                windows everything into (num_windows, window_length, 14) arrays.
ad/datagen.py   generate_synthetic_data(): builds a labeled evaluation set from
                X_test_normal by injecting one of 4 synthetic anomaly types (bias,
                spike, drift, noise) into half the windows. Saved in CMAPSS-style
                whitespace .txt format to data/synthetic/.
ad/models/      classical.py: GRU encoder -> (mu, logvar) bottleneck -> GRU decoder.
                quantum.py: PennyLane variants (bottleneck-only or fully quantum).
ad/train.py     Trains the VAE with a beta-annealed KL term (vae_loss), early
                stopping on val reconstruction+KL loss. Saves vae_checkpoint.pt +
                scaler.pkl.
ad/threshold.py Scores X_val deterministically (z=mu, no sampling from the latent
                distribution) and picks an anomaly threshold from a percentile of
                that healthy-only score distribution -- never touches synthetic
                labels, so the threshold can't be biased by them. Saves
                ad_threshold.json.
ad/evaluate.py  Scores the synthetic set (AUROC/AUPRC, precision/recall/F1 at the
                saved threshold, broken down by anomaly type) and, separately, the
                *unhealthy* portion of test engines (RUL < threshold, the rows
                prepare_data() normally discards) as a real-world sanity check with
                no ground truth -- just whether detection rate rises as engines
                approach failure.
```

### Running it

All commands run from the repo root (`ad/`'s imports are package-relative, e.g. `from ad.data import prepare_data`):

```bash
python -m ad.datagen                                  # builds data/synthetic/{synthetic,labels}_FD001.txt
python -m ad.train --beta-max 1.0                      # trains, saves vae_checkpoint.pt + scaler.pkl
# add --model quantum (--quantum_mode bottleneck|full) to use a PennyLane-based model instead of the default GRU-VAE
python -m ad.threshold --checkpoint vae_checkpoint.pt   # saves ad_threshold.json
python -m ad.evaluate --checkpoint vae_checkpoint.pt --scaler scaler.pkl
```

`--beta-max` (default `1.0`) controls how strongly the VAE's KL term is weighted after warmup — lower values (e.g. `0.1`–`0.3`) trade a less-regularized latent space for better reconstruction fidelity, which is the more promising lever if you want to push detection performance further without changing the scoring method.

### Scoring methodology

Reconstruction error alone isn't one number — how you reduce a window's per-cell squared error into a single anomaly score matters a lot, and different anomaly shapes favor different reductions:

- `mean` — average over the whole window. Favors persistent, multi-timestep anomalies (bias, drift); dilutes single-timestep or single-sensor anomalies.
- `topk_time` — mean of the k worst *timesteps* (each pre-averaged over all sensors). Better at spikes than `mean`, but still dilutes a single-sensor anomaly across the sensor count before ranking.
- `topk_cell` — mean of the k worst individual (timestep, sensor) cells, undiluted by averaging. Catches both single-sensor persistent anomalies and single-timestep spikes.
- `combined` (default) — an ensemble of `mean` + `topk_time` + `topk_cell`, each z-scored against its own healthy-validation distribution (their raw values aren't on comparable scales) and combined via `max` — an anomaly only needs to look anomalous under *one* reduction to be flagged. This is what `ad_threshold.json` currently holds, and gets AUROC 0.947 / AUPRC 0.956 / F1 0.860 on the synthetic benchmark, no anomaly type below ~62% recall.

`--percentile` (default 95, in `ad/threshold.py`) trades recall for false-positive rate — see `ad/evaluate.py --percentile-sweep 90,95,97,99` for the actual curve on your checkpoint before picking a different operating point.
